[p001]
# Token经济学：AI时代的新货币战争

[p002]
> 来源：[原文链接](https://mp.weixin.qq.com/s/_IJhLdQX42F4jTv1fOgihA)

[p003]
硅谷出现了一种新的炫富方式。不是跑车，不是股权，而是——你每天烧了多少 token。

[p004]
它甚至有了一个专门的词：Token-maxxing，意思是“把 token 用量拉到极限”。你每天消耗多少 token？能同时调度多少个 agent 运行？你的 token 吞吐量有多高？这些正在变成衡量一个人“有多 AI 原生”的新指标。

[p005]
而在这背后，一场围绕 token 的新军备竞赛已经全面打响。

[p006]
## Meta 的“烧 Token 排行榜”

[p007]
2026年4月，Meta 被曝内部有一个名为“Claudeonomics”的排行榜。它汇集了超过85000名员工的 AI 使用数据，列出了 token 消耗量最高的前250名“超级用户”。最近一个月，排行榜上的总使用量突破了60万亿 token。按照 Anthropic Opus 4.6大约每百万 token 15美元的定价粗略换算，这些 token 的价值高达约9亿美元。排名第一的那位员工，烧掉的 token 价值高达数百万美元。

[p008]
消息一出，硅谷立刻分成了两派。

[p009]
AI 创业公司 Writer 的 CEO May Habib 直接说这是“生死存亡级别的问题”。她自己公司内部也有一个 token 消耗排行榜，而且她明确告诉员工——她本人就在盯这个数据。她的逻辑很简单：不全力拥抱 AI，就会被淘汰。

[p010]
Uber 更加激进。目前 Uber 后端系统中，11%的新代码更新已经由 agent 完成，而三个月前这个比例还不到1%。Uber CTO 的愿景是把软件工程彻底转型为 agent 软件工程。

[p011]
但反对的声音同样尖锐。

[p012]
HubSpot 的 CEO Yamini Rangan 在 LinkedIn 上发了一句话被广泛转发：Outcome maxxing 大于 Token maxxing。她的意思是，比起疯狂消耗 token，不如看看你产出了什么结果——纯粹的 token 使用量，是一个错误的指标。AI 软件工程公司 Jellyfish 的 CEO 说得更直白：“你可以一天到晚刷 token，但得到的结果可能完全不是你想要的。”

[p013]
两派吵得不可开交。但一个中间派共识正在形成：不充分利用 AI 的公司，一定会被竞争对手超越，变得过时。在这样的信念下，哪怕排行榜和激励制度不完美，哪怕很多 AI 使用最终被证明是浪费的，大厂的创始人和高层们也被卷进来了——因为他们必须让公司转型为更 AI 原生的组织。

[p014]
## 一堂昂贵的 AI 成本课

[p015]
巨头们可以不计成本地烧 token，但对创业公司和个人开发者来说，token 成本带来的是实实在在的焦虑。

[p016]
用 OpenClaw 跑一个稍微复杂一点的任务，几千万 token 是非常有可能的。如果用的是最贵的 Claude 模型，让它做一件很小的事可能就要花十几二十美元。Uber 的 CTO 在接受采访时透露，公司2026年的 AI 预算在年初几个月内就已经全部用完了，主要是因为工程师们对 Claude Code 的使用量暴增。“我得重新回去做预算了，因为我以为够用一年的钱，已经没了。”

[p017]
硅谷知名投资人 Chamath Palihapitiya 最近也公开抱怨，他投资的一家软件公司自从团队开始使用 AI 编程工具之后，运营成本在几个月内翻了三倍多，年化 AI 支出将达到千万美元级别。他半开玩笑地说了一句：“感谢 VC 们掏钱为这场 AI 盛宴买单。”

[p018]
这里暴露了一个根本性的变化：对软件 SaaS 行业来说，AI 时代的成本结构跟过去完全不同了。

[p019]
以前做一个 SaaS 产品，研发投入是一次性的，用户越多，边际成本越低——这是一门越卖越赚的生意。但现在，每个用户的每一次操作背后都有一笔 token 账单在跑。用户用得越深，功能越智能，产品方反而要付更多的钱给模型厂商。这个成本不会像传统软件那样摊薄到接近零，它是跟着用量线性增长的。

[p020]
正因如此，token 正在变成 AI 创业公司最核心的“弹药”。已经有风投基金开始尝试直接给被投企业提供 token 额度作为投资的一部分——逻辑很简单，很多 AI 创业项目拿到钱之后第一件事就是去买 token。那为什么不能直接给 token 呢？

[p021]
顺着这个逻辑往下推，一个更大的问题浮现出来：token 是不是正在变成一种新的货币？

[p022]
## Token 到底怎么定价？

[p023]
Token 的定价远不是一个“单价乘以数量”那么简单。

[p024]
以一次最简单的对话交互为例，你的账单上至少有三种不同价格的 token 在运转：

[p025]
第一是**输入 token** ，也就是你发给模型的内容。第二是**缓存输入 token** ——如果某些 prompt、上下文或文件内容之前已经被模型系统缓存过，再次调用时这部分 token 的价格会便宜得多。第三是**输出 token** ，即模型生成回答时产生的 token。

[p026]
研究 Token 效率方向的专家肖志斌指出，在对话任务上，这三者的价格比例大约是1:0.1:6。缓存命中时，成本基本只有输入 token 的十分之一，而输出成本通常是输入的6倍。

[p027]
不同模型公司的定价差异巨大。GPT-5的 API 定价是：输入每百万 token 1.25美元，缓存输入0.125美元，输出10美元。而最新发布的 GPT-5.5，短上下文输入涨到了5美元，缓存0.5美元，输出30美元。最顶级的 GPT-5.5-pro 和 GPT-5.4-pro，短上下文输入每百万 token 30美元，输出180美元，长上下文还要再贵一倍。

[p028]
乍一看，涨价了好几倍。但这里藏着一个反直觉的悖论：**越贵的模型，总体成本可能反而越低。**

[p029]
原因很简单：强模型一次就能做对，弱模型可能要反复重试，中间出错还要人工介入。虽然 token 单价在涨，但每个有效结论的综合成本反而在下降。这在 agent 场景中尤其明显——agent 不是一问一答，它会来回调用模型，每一步可能调用不同的工具，工具又产生新的日志和上下文，形成持续的循环。质量高的模型可能一次就生成正确答案，调用的工具也合适；而便宜模型可能花费更多时间反复迭代，甚至中途出错。

[p030]
定价的另一个关键维度是按模型质量而非推理成本。很多公司按照推理成本定价，但这其实是不可取的——应该按照模型对任务的完成度来定价。这里的价值空间，远没有被充分挖掘。

[p031]
此外还有云厂商这一派玩家。微软 Azure、亚马逊 AWS，以及国内的阿里云和火山引擎，企业通过它们调用模型时，账单是模型 token 费用加云服务封装费，再加企业级基础设施溢价——区域部署、数据驻留、企业合规、优先推理、私有化吞吐，每一项都是加价理由。

[p032]
## 中国模型的“物美价廉”奇袭

[p033]
当 OpenClaw 让 token 消耗从万级跳到百万级，一个现象出现了：来自中国的模型，因为性价比，开始在国际开发者社群中迅速走红。

[p034]
Kimi 的输入价格不到55美分/百万 token，输出约2.6美元。MiniMax 更是受到了 OpenClaw 官方推荐——在软件选模型界面，MiniMax 后面直接标注了“recommended”。虽然顶级推理能力可能差一些，但很多工作本来就不需要那么高的推理能力。执行类任务，反而要求指令遵循好、做得快，最重要的还是便宜。

[p035]
在某些任务上，中美模型的价差可以高达50到70倍。

[p036]
一个直接的对比：MiniMax M2.5和 Claude Opus 4.6在 SWE-Bench Verified 软件工程基准测试中，得分分别是80.2%和80.8%——这点差距在实际使用中几乎感受不到。但价格表就完全不同了。MiniMax M2.5的输入价格是每百万 token 0.3美元，Claude Opus 4.6是5美元。同样的活，前者价格只有后者的1/17。对于一个每天跑几千万 token 的 OpenClaw 用户来说，这不是省一杯咖啡钱的问题，而是账单从几百美元直接降到几十美元的区别。

[p037]
中国模型凭什么做到这么便宜？三方面的因素。技术上，深度使用 MoE（混合专家模型），专家规模越来越小，每次激活的专家数目也不大，极大节省了推理成本。生态上，各家公司通过补贴用户抢占市场。商业模式上，像阿里这样的公司本身是云厂商，自带更高的利润率空间，能把模型价格压得更低。

[p038]
这场奇袭已经有数字为证。OpenClaw 爆火后，agent 任务对开源模型的调用需求飙升，智谱和 MiniMax 的股价迎来疯狂涨幅。2026年3月，国内三大云厂商（腾讯云、阿里云、百度智能云）10天之内接连涨价30%左右——需求太猛了。开源模型的能力已经越过了一个关键门槛。尤其是编程赛道——token 消耗最大的赛道之一——当程序员发现开源模型和几个月前的 Anthropic 模型一样好用但价格极其便宜时，切换是本能。

[p039]
不同模型正在形成自然分工：复杂任务交给高性能模型，简单或重复性高的任务交给便宜模型。这种混合使用，成了 agent 时代的新 token 模式。

[p040]
## 中间商的时代：OpenRouter 与 Metronome

[p041]
在这场 token 大潮中，最赚钱的不一定是模型公司。

[p042]
OpenRouter 已经成了观察全球模型使用趋势的一面镜子。你看过的很多关于中国模型调用和排名的数据图，都出自这个平台。创始人 Alex Atallah 上一个身份是全球最大 NFT 交易所 OpenSea 的联合创始人兼 CTO。2023年他开始做 OpenRouter，逻辑极其简单：市面上模型越来越多，开发者不想每家单独注册、充值、对接 API 格式。OpenRouter 做了一个统一入口，所有模型一个接口搞定，平台抽大约5%的费用。

[p043]
据 The Information 报道，A16z 在2025年领投了4000万美元，当时估值约5亿美元。最新一轮融资已将估值推至接近13亿美元。真正让这门生意起飞的，是 OpenClaw 的爆发——当全球开发者疯狂调用各种模型驱动 agent 工作流时，他们需要一个能快速切换模型的中间层，而 OpenRouter 恰好就在那里等着。

[p044]
Atallah 把这次创业和上一次做过类比：两次都是把分散的供给整合到一个平台上。他赌的是，供给越分散，中间商越值钱。

[p045]
当然，OpenRouter 也有数据盲区。从1到10的公司会混用 OpenRouter 和直连 API，大厂则直接调用 Anthropic、OpenAI 或 Google 的 API。所以 OpenRouter 的数据更像是创业公司和独立开发者群体的风向标，而非整个 AI 行业的全景图。但恰恰是这个群体，对价格最敏感，对新模型最愿意尝鲜，迁移成本也最低——他们构成了中国模型出海的第一波“自来水”用户。

[p046]
如果说 token 是 AI 时代的“电”，那总得有人装电表。Metronome 就是这么一家公司。

[p047]
这家公司的客户名单看一眼就知其分量：OpenAI、NVIDIA、Anthropic、Databricks，全在用它的计费系统。两位创始人出自 Dropbox，在那里亲身经历过一个让所有 SaaS 工程师头痛的事——改定价。表面上只是把月费调几块钱，背后却要动一大堆写死在代码里的计费逻辑。到了 AI 时代，这个痛点被放大了几个数量级：收费单位不再是“一个人头一个月多少钱”，而是 token 数、API 调用次数、GPU 时长——这些颗粒度极细的指标，而且每个客户的合同条款、折扣结构和用量阶梯可能都不一样。

[p048]
Metronome 的核心设计是把“发生了什么”和“该怎么收费”这两套逻辑彻底拆开。工程团队只管上报用量数据，产品和销售团队自己配置价格和合同条款，中间的换算、出账、对账全部自动化。它把计费分成四层：第一层记录 API 交互事件（读还是写、是否命中缓存、模型是否在做推理）；第二层是事件流的定价；第三层是计费方式（订阅、按量、限额加超量）；第四层是折扣打包。

[p049]
这家100人的公司累计融资1.28亿美元，2026年1月被 Stripe 收购，估值追上了很多做模型的公司。这本身就说明——在 token 经济里，怎么算钱，正在变得和怎么造模型一样重要。

[p050]
## Token 套利：AI 时代的差价生意

[p051]
当开发者们开始把不同模型混着用——复杂任务用 Claude 和 GPT，简单任务用 MiniMax 和 Kimi——一种新的商业模式浮出水面：Token 套利。

[p052]
这个逻辑有点像运营商套餐：你买了千兆下行带宽，给你配了40兆上行，但普通用户感受不到。token 也一样，全都用便宜模型和全都用贵模型，在用户看来区别可能不大。这里就有了套利空间：先按复杂模型的使用量定价，设好30%的利润率。一旦用户接受了这个价格，就开始用便宜 token 替换贵 token。只要用户感知不出体感或表现上的变化，他们付的仍然是高价值 token 的钱。

[p053]
更进阶的做法不是简单“批发转零售”，而是搭建一个“智能路由器”：用户需求进来后，先用一个模型判断任务复杂度，简单任务分配给便宜模型，只有真正复杂的才交给 Claude 或 GPT。对用户来说是黑盒，但中间商在持续优化成本结构。

[p054]
理论上，每家模型提供商都该有自己的“路由模型”——一个专门判断任务难易程度、然后分配最合适模型的小模型。像 Genspark 和 Manus 这样的 AI 产品，内部已经在基于 benchmark 和经验对不同任务做灵活分发。OpenClaw 社区也有人开发了 token 自动调优器，能针对不同任务进一步细分。

[p055]
这种套利可持续吗？大模型厂商已经在把自己的产品内置这种能力——比如 Anthropic 在 coding agent 中加入了 Advisor 模式，先用贵模型判断哪些任务可以用便宜模型做。但跨模型的调度空间远没有被穷尽。每家大模型公司只优化自己的模型，而市场上的模型实在太多了。跨模型的智能调度，需要做的远不止 API 聚合和统一定价——还需要任务与模型的精准匹配、吞吐量和延迟的判断、模型质量与任务完成度的评估，甚至模型与硬件的匹配。

[p056]
最终的赢家，可能是最会调度 token 的系统。

[p057]
## Token 出海：下一个结构性产业机会？

[p059]
当一个伦敦的程序员用 MiniMax 的 API 跑 OpenClaw 时，物理层面上发生了什么？他的请求从英国出发，穿过海底光缆，落在贵州的数据中心里。GPU 开始工作，风扇开始转，电表开始跳。几秒钟后，结果原路返回。

[p060]
整个过程没有一度电离开过中国电网。但这度电的价值，已经通过 API 账单，以 token 的形式完成了跨境结算。

[p061]
这是一种全新形态的出口。中国过去出口日用品、衬衫、家电，后来是电动车——但这些都是实物，要过海关。Token 出海不需要集装箱，甚至不需要任何实体商品离开国境。电力在本地消耗，算力在本地运转，但创造的价值通过互联网瞬间交付到全球任何一个开发者手上。有人把这叫做“电力出海”——虽然电没出去，但电的价值出去了。

[p062]
那么中国 token 能一直这么便宜吗？很多人的第一反应是电价优势。但实际情况更复杂。

[p063]
GMI Cloud 创始人 Alex 给出了一个直率的判断：美国其实不缺电，缺的是配电能力。高压电上多的是电，天然气一烧电就出来了，但要把电传到一个具体地点——建变电站、从330kV 一路降到400V 或800V——这是一个极其冗长、光审批就能让人爆炸的过程。中美电力成本的绝对值差异并不大：中国工业用电0.4到0.6元/度，美国0.8到1.2元/度。真正拉开差距的是基础设施的响应速度：中国可以在西部沙漠里铺满光伏板，再通过特高压电网把电送到东部的算力集群。

[p064]
从供应链角度看，token 价格短期内更难下降。DRAM 价格涨到了过去的10倍，CX7缺货，电源供应也在缺货。OpenClaw 起来了，agent 起来了，多模态起来了，coding 起来了——四个完美风暴撞在一起，所有供应链都跟不上节奏。最大的挑战是物理上的：建足够多的数据中心，有足够多的卡，通足够多的电。

[p065]
但出海趋势已经在迅速发生。MiniMax 海外收入占比超过了七成。月之暗面在 Kimi K2.5发布后，短短数周内收入就超过了2025年全年。智谱的模型 API 收入也在今年出现了爆发式增长。

[p066]
天花板还远远没有到。大部分人还只是偶尔用用 agent，大部分行业还远没有被 agent 渗透。但趋势已经很清楚了：token 消耗正在从“人类主动发起”变成“机器自动运转”。一个程序员手动用 AI 编程助手，一天可能烧几十万 token；一旦配了一个 agent 全天候在后台跑——写代码、查资料、跑测试、发部署——消耗量直接跳到千万级。当这种使用方式从少数极客扩散到普通开发者，再扩散到每一个知识工作者，token 需求的增长就是指数级别。

[p067]
上一个时代中国出口的是衬衫和家电，这个时代是电动车——那么下一个时代，很可能就是 token。

[p068]
## 结尾：一切才刚刚开始

[p069]
Token 到底意味着什么？

[p070]
对 Meta 员工来说，它是排行榜上的勋章。对创业公司来说，它是每个月最大的一笔开支。对 OpenRouter 来说，它是抽5%佣金的流水。对中国的云厂商来说，它是把电力变成美元的管道。对黄仁勋来说，token 是一种大宗商品——每一个输入和输出都与芯片挂钩。

[p071]
未来，人类几千年来发明过的所有商业模式——期货、套利、批发零售、聚合平台、计量计费——都会在 token 身上重新演一遍。定价方式也在发生巨变：按复杂度计费、按任务完成度计费，这些新模式正在浮现。就像原油到汽油再到续航里程，token 到任务再到业务结果，这条进化路径上的定价逻辑也会被完整复现。

[p072]
唯一不同的，是速度。这一切不是在几十年里慢慢展开的，而是在几个月内迅速发生的。
