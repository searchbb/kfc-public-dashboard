[p001]
# Visa 最新研究：1.1 亿笔交易背后，Agent 支付正在重构互联网商业

[p002]
撰文：Tim Conard（Visa 链上数据负责人）、Lucas Shin（Artemis 数据与研究）

[p003]
编译：佳欢，ChainCatcher

[p005]
Artemis 是链上数据领域的分析平台，Visa、Grayscale、Pantera、VanEck、Tether、Circle 等机构都在用它判断链上和链下究竟在发生什么。这份报告用的是 Artemis Analytics 的自有数据集，覆盖 x402 和 Machine Payments Protocol 上的真实交易活动、经欺诈调整的指标，以及生态增长情况。

[p006]
Visa 成立之初的目标不只是做一张卡的网络，而是要建一套全球性的价值安全交换系统，不依赖某种特定技术或形态。代理型商业是这条演化路线上的新前沿。当软件开始替用户和企业发现、评估、购买商品与服务，新的基础设施会随之出现，用来在机器速度下支撑信任、授权、结算和控制。

[p007]
这个新品类有可能改变支付被发起、被路由、被嵌入数字工作流的方式。这份和 Artemis Analytics 合作完成的研究，看的是今天围绕代理支付正在成形的协议、标准、数据和市场结构，希望帮支付网络、发卡行、收单方、金融科技平台和企业团队看清这块新的交易面在怎么发育，最重要的机会和挑战大概会出现在哪里。

[p009]
1.1 定义代理型商业

[p010]
代理型商业是一种新兴经济形态：软件能够持续、自动地发现、评估并执行交易，其交易规模和运行方式都超出了传统支付基础设施最初的设计范围。

[p011]
自主程度有高有低。有些工作流仍然保留人在环节里审核或批准购买，有些一旦配置完成就完全自动运行。代理可以买 SaaS 席位、订差旅、自动处理应付账款、补实物库存、外包创意工作，很多时候在下单那一刻并没有人介入。

[p012]
在这个大范围里，还冒出了一个新的子类：机器原生的、一美元以下的交易。AI 代理调用一个 API，收到 HTTP 402 响应（Payment Required），评估价格，付款，然后消费这个资源。整个循环耗时毫秒级，不需要结账页、不需要存好的卡、也不需要浏览会话，只需要一个钱包或一张卡、一笔预算和一个目标。

[p013]
对支付服务商来说，代理型商业涵盖多种新的交易类型，其经济模型、风控要求和基础设施需求都不同于传统电商。

[p014]
AI 从聊天机器人迈向自主代理的标志，是它开始能够规划和处理多步骤任务、调用外部工具、评估结果，并自主调整执行策略。基于 Claude、GPT、Gemini 这类前沿模型构建的代理，现在已经在各个业务垂直领域投入生产环境。过去一年里，这些代理在写代码和做研究上变得非常能干，但它们天生受限于「能不能拿到东西」。

[p015]
让代理具备付款能力，这个限制就被解除了：

[p016]
- IT 代理在人员编制变动后，在 SaaS 平台上追加购买五十个席位。
- 行政代理在库存不足时，重新订购打印机墨粉和茶水间用品。
- 研究代理为同一家公司的申报文件，向五家金融数据商各花几美分查询，然后挑出最完整的那份数据。
- 营销代理向十家图像生成服务商各付 5 美分，渲染同一张产品图，再选出最好的输出。
代理支付跨越两类差别明显的交易。 第一类是宏观交易，代理替人执行高价值、类消费者的购买，比如订差旅、管理订阅、采购物资。这类交易和传统电商很像，代理扮演的是人类意图的代理人。第二类是微观交易，特征是高频、低价值的购买，由代理自己发起，比如 API 调用、数据查询、算力访问、工具使用。

[p017]
两类都真实存在且都在增长，但微观交易才是最需要新支付架构的地方，也是新协议正在填补的缺口。

[p018]
过去十二个月，有两个开源支付协议上线来支撑第二类代理支付。x402（由 Linux 基金会持有，Coinbase 和 Cloudflare 孵化）自 2025 年 5 月以来处理了超过 1.357 亿美元交易额，交易笔数 1.783 亿笔。Machine Payments Protocol（由 Stripe 和 Tempo 开发，Visa 参与贡献）自 2026 年 3 月中旬上线以来结算超过 3.8 万美元，交易笔数约 18.46 万笔。

[p019]
以上为原始链上累计口径，剔除刷量与测试后的调整口径见方法说明与第四章。

[p021]
1997 年，在线商业才刚起步。亚马逊卖书两年，PayPal 还不存在。在设计商用互联网底层协议时，工程师预留了 402 状态码（Payment Required），设想未来支付可以像加载网页一样，成为互联网的原生功能。

[p022]
真正的变化并不只是基础设施升级，而是市场第一次出现了规模化、机器原生的支付需求。

[p023]
最关键的进展是 AI 跨过了一道能力门槛。自 2025 年年中 Claude 4.5 和 GPT Codex 5.2 发布以来，代理已经能够发现陌生的 API、理解它们提供什么、评估价格并决定是否付款，全程自主、以机器速度进行，每笔交易发生时都不需要人来批准。

[p024]
这种能力催生出一种此前不存在的有机需求：以程序化、按需的方式获取 API、数据、算力和服务。代理需要持续地、大批量地付钱，同时不能有注册账号、事先谈合同、手工走结账流程这些摩擦。

[p025]
新的结算基础设施跟着这个需求信号出现。新一代区块链把数字支付的成本和结算速度同时改善了数个量级。Tempo 这类专门为支付构建的链，现在能做到亚美分级费用和 500 毫秒结算。Base、Solana 这类成熟链上，gas 成本已经降到一美分的零头，让 0.01 至 1.00 美元区间的微支付第一次在经济上成立。

[p026]
关键在于，这套基础设施本身并没有创造出代理型商业的需求。专用链已经存在多年，也没有自发长出按用量计费的 API 市场。真正推动市场形成的，是能力不断增强的 AI 代理所产生的实际需求。

[p027]
除了更好的结算经济性，区块链通道也变得更容易集成，且不必暴露底层复杂度：账户抽象、MPC 钱包、passkey、代付交易，越来越多地让这些通道退到后台，对终端用户、商户和企业团队都是隐形的。

[p028]
Coinbase 在 2025 年 5 月上线 x402，Tempo 在 2026 年 3 月上线 MPP。几个月内，两个协议都跑出了真实的生产流量。有能力的代理创造了需求，新协议和新通道让服务这批需求变得划算。

[p029]
对现有机构来说，不作为的风险是被脱媒。如果少数几个平台同时掌握代理支付的需求和交易路由，它们就能把支付流拉到现有网络之外，微支付密集、传统卡经济模型最弱的品类尤其如此。一旦这个板块在传统支付栈之外形成规模，只通过高价值代理交易参与的现有机构，可能会错过新兴代理经济中频次最高的那一部分。

[p030]
能把协议原生的速度，与现有机构级别的信任、合规和分发能力结合起来的玩家，最有条件定义下一代代理支付基础设施。

[p031]
二、交易形态与新的架构需求

[p032]
2.1 一种新的交易模式

[p033]
代理支付看上去可能和人类商业毫无相似之处。一个人一天可能就做几笔购买，每笔都是深思熟虑的，商户也是他早就认识的。一个执行研究任务的代理，可能一小时内做几百笔购买，每笔几美分甚至更少，每笔都来自它刚刚发现的不同供应方。

[p034]
三个维度定义了代理交易的形态：频次、金额、关系。 人类商业里，交易是低频、中高价值的，发生在已有关系的双方之间，比如一个账号、一份订阅、一张存好的支付方式。

[p035]
在代理型商业的微观交易类别里，交易是高频、低价值的，发生在完全没有过往关系的双方之间。代理发现一个服务，评估价格，付款，然后走人。付款是买卖双方之间唯一的交互。

[p036]
代理型商业让直接的、按用量的交换在任何价位上都成为可能，付款可以挂到单次查询、单次工具调用、单次数据请求上，小到一美分的零头。在那个世界里，工作和付款变得不可分割。

[p037]
随着代理型商业扩大规模，交易笔数的增长很可能远快于金额增长。一次只花几美元的代理会话，可能产生几百甚至上千笔独立付款，因此，任何采用逐笔授权机制的系统，在处理相同交易金额时，都必须完成比今天多得多的授权决策。

[p038]
2.2 为什么代理微支付需要新架构

[p039]
卡的技术栈是为人类商业专门构建的：更少的交易笔数、更大的客单价、事先建立好的商户关系。代理型商业中的高频、亚美元（1 美元以下的小额交易）微支付，与传统卡支付的交易特征截然不同，因此需要在现有卡支付体系之上增加新的架构层。

[p040]
差异体现在好几个维度上。卡通道针对法币计价购买、秒级授权、天级结算和人工验证流程做了优化。机器原生的微支付板块提出了新要求：亚美分级的支付经济性、近乎即时的确认、机器可读的凭证，以及在没有事先商户关系的前提下高频交易的能力。

[p041]
订阅制和计量计费能绕开其中一部分约束，但代价是必须注册账号、事先谈好定价、维持一段持续的商业关系。这个模式对已知客户有效，对一个「发现服务、付一次钱、然后走人」的代理无效。

[p042]
机器原生微支付的要求｜来源：Artemis，数据截至 2026 年 5 月

[p043]
上面这张表说明了机器原生微支付在哪里需要新架构，但卡并不是一套僵硬、静态的技术栈。它是可以被扩展、可以在其上继续构建的柔性基础设施，行业头部正在积极探索这一点。

[p044]
Visa 的 Trusted Agent Protocol（TAP）、Visa Intelligent Commerce（VIC），以及面向 MPP 的 Visa Card Specification，都在演示卡基础设施如何被改造来支撑代理发起的交易，从较高价值的代理人购买一直到机器原生的支付流。

[p045]
因此，新型微支付协议并不是要取代银行卡，而是在现有卡支付体系之上，覆盖过去因成本过高而无法服务的小额交易场景。

[p046]
这也正是新支付协议必要且正在涌现的原因。它们让付款成为买卖双方之间第一次也是唯一一次交互，由此催生出一类新商户：API、工具服务器、卖微服务的开发者、按次查询收费的数据提供方。这些生意需要机器可读的支付流、接近零的接入摩擦，以及在极小金额上仍然成立的交易经济性。

[p049]
HTTP 402 自 1997 年起就是 Web 规范的一部分。它的设计意图，是让服务器（比如一个网页）告诉客户端（比如一个用户）：资源存在，但需要付款才能访问。x402 和 MPP 是头两个在这个沉睡了近三十年的状态码之上构建生产级支付基础设施的协议。

[p050]
两个协议都遵循下面这个基本流程：

[p051]
- 客户端向服务器发出一个 HTTP 请求
- 服务器返回 402 状态码和一组支付要求：价格、接受的币种、往哪里付
- 客户端评估条款，附上付款，带着凭证重新提交请求
- 服务器验证付款，交付资源
整个交换直接发生在 HTTP 请求与响应的交互内部，没有跳转到支付页，也没有独立的结账流程或商户集成。付款的工作方式和今天 Web 上的认证一样，走 HTTP 请求里的 header。任何服务器只要返回一个 402，就能变成付费端点，也就意味着任何有钱的代理都能原生地为它付款。

[p052]
3.2 MPP：双方结算

[p053]
信任模型。 MPP 没有中间方。代理直接付给服务器，服务器交付资源。

[p054]
结算。 主结算通道是 Tempo，一条专为支付构建的区块链，最终性约 500 毫秒，费用低于千分之一美元。Tempo 还支持代付（gasless）交易，也就是代理或服务器可以替对方承担 gas 费，降低新参与者的摩擦。

[p055]
MPP 还通过 Visa 的 Card Specification 和 Stripe 的集成原生支持卡，同一协议内也支持闪电网络。一台服务器可以同时提供多种支付选项，代理用同一套协议流程选择它偏好的任意通道。这个设计把更多价值推向交易之上的平台层、工具层和信任层。

[p056]
支付类型。 MPP 目前支持两种付款方式。第一种是 charge，一次性付款，代理付钱，服务器交付。单笔 charge 可以在一笔交易内原子化地拆分给最多十个接收方，这让市场平台模式和收入分成得以在协议层实现。

[p057]
第二种是 session，一条流式支付通道，代理把资金存入链上托管，服务器增量交付价值。代理在消费服务的过程中签发链下凭证，授权服务器认领已交付价值对应的款项。服务器可以在微秒级验证这些凭证，不必每次请求都发起一次链上调用，让 session 的运行速度接近一次标准 API 调用。未消费的资金可以退还给代理，服务器在会话结束时批量结算凭证。

[p058]
治理。 MPP 在 IETF 标准轨道上开发（draft-httpauth-payment）。IETF（互联网工程任务组）是驱动互联网的多数核心技术标准的责任机构，包括 HTTP 本身、TLS（HTTPS 背后的加密）和 DNS。进入 IETF 标准轨道意味着协议要走一套正式、公开的评审流程，任何工程师或组织都可以参与、评论、提出修改。这让 MPP 成为唯一一个通过「产出了互联网基础协议的同一套流程」开发的代理支付协议。规范公开可得，设计上保持厂商中立。

[p059]
3.3 x402：三方结算

[p060]
信任模型。 x402 在交换中引入了第三方，称为 facilitator（撮合方）。代理通过 x402 为某个资源付款时，款项先到 facilitator 手里，由它持有资金、验证服务器是否交付了承诺的东西，确认后才把钱释放给卖方。

[p061]
结算。 x402 是一个开放支付协议，设计上可以在任何部署了 facilitator 的链上运行，不限于某个固定的区块链集合。实际情况是，今天的活动集中在 Base、Solana 和 Polygon 上，其中 Base 承载了绝大部分交易额。这些链上的付款以稳定币在链上结算，主要是 USDC。

[p062]
facilitator 架构本身也与通道无关。虽然目前的 facilitator 主要在链上结算，但这套架构同样兼容通过 ACH、SEPA 或卡网络等传统通道结算的 facilitator。这个结构让 facilitator 成为 x402 模型中关键的变现层和信任层。

[p063]
支付类型。 x402 目前支持标准的固定价格付款，以及一种叫 Upto 的按消费计费模式。用 Upto 时，代理授权一个上限金额，只为实际消耗的部分付费。这是为那些代理事先并不知道自己会用掉多少资源的可变负载设计的。

[p064]
治理。 x402 最初由 Coinbase 创建，是一份专有规范。2026 年 4 月，协议的托管权移交给 Linux 基金会，后者成立了 x402 基金会作为厂商中立的治理机构。x402 基金会最初由 Coinbase、Cloudflare 和 Stripe 共同推动，启动时获得的支持方包括 Visa、Amazon Web Services、American Express、Base、Circle、Fiserv Merchant Solutions、Google、KakaoPay、Mastercard、Merit Systems、Microsoft、Polygon Labs、Shopify 和 Solana 基金会。

[p065]
转向 Linux 基金会下的开放治理，释放的信号是要把 x402 固化为一项共享的行业标准，而不是单一公司的项目。

[p066]
3.4 这些差异意味着什么

[p067]
两个协议都很新，都在演进。上面描述的链、支付方式、币种和功能，反映的是今天已经上线的状态。

[p068]
两套架构都被设计成可扩展的：x402 与通道无关的 facilitator 模型，意味着接入一个新 facilitator 就能加入任何新结算通道；MPP 的多通道设计，意味着新的支付方式可以在协议层被支持。随着两个协议成熟，功能集会继续扩张。

[p070]
除非另有说明，本章所有指标均按 Artemis Analytics 的自有方法论做过调整。

[p071]
4.1 x402：11 个月的实时数据

[p072]
x402 累计交易额（调整后），2025 年 10 月 20 日至 2026 年 4 月 21 日｜来源：Artemis

[p073]
x402 自 2025 年 5 月上线以来，处理了 1500 万美元调整后交易额，调整后交易笔数 1.096 亿笔。活动在 2025 年 10 月急剧提速，月度交易笔数从约 4 万涨到 380 万。仅 2025 年 11 月一个月，协议就处理了约 3800 万笔交易。

[p074]
x402 平均单笔交易金额（调整后）｜来源：Artemis

[p075]
交易笔数和交易额随时间出现了明显背离。2025 年 11 月是按笔数计的活动峰值月，3800 万笔产生了 515 万美元调整后交易额。2026 年 3 月呈现出完全不同的形态，164 万美元调整后交易额只对应 210 万笔交易，单笔均值是有记录以来最高的一个月。

[p076]
前 1% 的买方（约 4000 个钱包）占了约 90% 的调整后交易额和约 50% 的调整后交易笔数。这种集中度推高了平均单笔金额。不过更宽泛的趋势仍然说明，x402 支撑的支付规模和工作流组合，比「微支付」这个词本身所暗示的要更广。

[p077]
x402 分链交易笔数（调整后）｜来源：Artemis

[p078]
链上分布。 Base 压倒性地主导了这个生态，占到约 90% 的调整后交易笔数和 93% 的调整后交易额。Solana 按交易笔数排第二，Polygon 第三。就现阶段而言，x402 明显是一个以 Base 为中心的市场，其他链贡献的活动有意义但仍属次要。

[p079]
x402 分品类交易笔数占比（调整后）｜来源：Artemis

[p080]
品类分布。 按交易笔数计，Agent-to-Agent Services（代理对代理服务）是遥遥领先的最大品类，这正反映了定义机器原生商业的那种高频、低价值交易模式。

[p081]
这个品类捕捉的是链式工作流：一个代理为某个子任务付钱给另一个代理，比如数据检索、任务执行、推理，也就是说单次用户请求可以生成一连串交易。未被归类的长尾端点占了大部分交易额，凸显出供给侧的碎片化，以及对更好的发现和聚合工具的需求。

[p082]
x402 买方支出集中度（调整后）｜来源：Artemis

[p083]
买方集中度。 美元支出高度集中在很窄的一批买方手里。不到 0.02% 的买方产生了约 48% 的调整后交易额。这与一个早期市场的特征一致：即便整体参与者基数在扩大，仍然是相对少量的成熟参与者驱动着大部分经济活动。截至目前，x402 有超过 42.2 万个调整后买方。

[p084]
x402 累计卖方数量（调整后）｜来源：Artemis

[p085]
供给侧。 x402 至今记录到约 5300 个调整后卖方（即商户）。传统商户接入往往要几周时间并需要一家支付处理商，而在 x402 上，任何开发者都可以部署一个可收款端点，立刻开始接受付款。

[p086]
有两股顺风说明代理可消费资源的供给侧会继续扩张：第一，AI 正在降低创造数字产品的门槛，意味着会有更多人和代理成为商户；第二，新的 Web 服务和应用越来越多地是为代理设计的，API 优先、即时可访问、按请求定价。

[p087]
4.2 Machine Payments Protocol：上线头 33 天

[p088]
MPP 在 2026 年 3 月中旬上线，在本次分析时点刚上线一个多月。考虑到协议还处在早期阶段，细粒度拆分的意义不如 x402 那么大，这里的重点放在总量活动，以及 MPP 两种支付类型之间正在浮现的结构性差异。

[p089]
MPP 累计交易笔数（调整后），2026 年 3 月 18 日至 4 月 21 日｜来源：Artemis

[p090]
MPP 上线以来处理了约 2.5 万美元调整后交易额，调整后交易笔数约 11.5 万笔。交易增长从第一天起就稳定且大致呈线性，日均约 4000 笔调整后交易。

[p091]
MPP 按支付类型划分的交易额（调整后），charge 与 session｜来源：Artemis

[p092]
charge 占到 97% 的调整后交易笔数。session 的单笔金额显著更大，但在整体活动中仍是很小的一部分。如 3.2 节所述，session 允许代理把资金存入链上托管通道，在消费服务的过程中增量付费。由于服务器是批量结算累积的凭证而不是逐次请求结算，即便底层用量是细粒度的，单笔 session 交易看上去也会比 charge 大。早期 session 活动说明这个模式正在被试用，但还没有获得广泛采用。

[p093]
MPP 按支付类型划分的平均单笔金额（调整后）｜来源：Artemis

[p094]
交易额是逐步累积的，大多数交易仍在亚美分区间。charge 的平均单笔金额在这段时间里一直平稳维持在 0.17 美元附近，session 的平均单笔金额是 2.15 美元。session 单笔金额的上行，很可能反映的是开发者在测试流式支付模型时用了更大的存款金额来做实验。

[p095]
MPP 累计买方与卖方数量（调整后）｜来源：Artemis

[p096]
MPP 至今记录到超过 2800 个调整后买方和 90 个调整后卖方。约 32:1 的买卖方比例说明需求跑在供给前面，越来越多的代理在一批仍然有限的可用端点上交易。供给侧仍然发育不足。x402 在最初几个月的卖方数量也是类似量级，之后才开始急剧加速。

[p097]
五、信任、身份、支出控制与争议处理

[p098]
5.1 代理信任是最难的问题

[p099]
传统商业默认买方是人，具备意图、判断力和可追责性。代理型商业对这三点都提出了问题。买方是一段基于授权行事的软件，以机器速度做决策，往往没有实时的人工监督。这带来了一个信任问题，任何一个协议单靠协议层都无法完全解决。

[p100]
买错风险。 最简单的失效模式是代理买错了东西。代理误解了任务、选错了服务，或者为某个资源付了过高的价格。人类商业里，买方在结账前会发现错误，或者事后发起争议。

[p101]
自主运行的代理可能根本意识不到这个错误，而在机器速度下，一个配置有误的代理可以在任何人注意到之前执行几百笔糟糕的交易，制造出规模上难以收拾的对账、退款和争议负担。

[p102]
对抗性攻击。 提示词注入，也就是恶意输入操纵代理去执行未授权的动作，目前仍是一个活跃的研究领域，没有完整解法。攻破代理推理过程的攻击者可以重定向购买、盗走资金，或者在相连的多个服务上触发未授权支出。攻击面随自主度增长：代理交易的自由度越高，一个被攻破的代理能造成的破坏就越大。

[p103]
责任归属。 当代理做出一笔未授权购买，责任方一开始可能并不清楚。授出权限的那个人、托管代理的平台、推理出错的模型提供方、接受了这笔付款的商户，各方都有站得住的主张和抗辩。现有的法律和监管框架不是为这条委托链设计的，明确的先例也未必存在。

[p104]
连锁失败。 随着代理型商业成熟，代理会越来越多地与其他代理交易，而不是直接与商户交易。一个合规代理可能付钱给文档审阅代理来分析合同，后者又付钱给法律研究代理去检索相关判例，再由后者付钱给数据库代理去调取法院文件。

[p105]
这类代理对代理的链条通过专业分工创造价值，但也通过相互依赖引入了风险。如果链条中任何一个代理交付了糟糕的结果，它上游的每一个代理都已经为基于这个输出的工作付过钱了。要纠正这个错误，就需要把争议沿着链条逐环向后传导。这种多跳支付链在传统商业里没有对应物，也不存在解开它们的既有处理机制。

[p106]
5.2 当前的解决方案

[p107]
上面这些信任挑战，正在技术栈的多个层面被处理，加密原生和卡原生两边的玩家都在动。

[p108]
协议层。 x402 和 MPP 这类支付协议正在把信任直接构建进交易机制里。第三方 facilitator 的做法可以在释放资金前验证交付，托管机制让买方只为已消费的价值付费，按消费计费的授权则通过给单次请求的支出封顶来限制敞口。这些都是协议级的防护，但效果取决于买卖双方选择使用哪个协议、哪种支付类型。

[p109]
身份层。 生态仍然是碎片化的。多数代理用 API key 或钱包地址做认证，这能验证访问权限，但对历史记录和可靠性什么也说明不了。

[p110]
x402scan、MPPscan 这类公开注册表提供基础的端点发现。Coinbase 的 Bazaar 注册表把商户映射到收款地址。ERC-8004（Trustless Agents Standard）的目标是让代理声誉可以跨网络携带，让商户在决定是否交易之前先核验代理的交易历史。

[p111]
卡这一侧，Visa 的 TAP、Mastercard 的 Agent Pay、以及 Stripe 与 OpenAI 的 ACP，帮助把代理身份锚定到现有授权框架上，继承了几十年积累的 KYC 和风控基础设施，但都与卡通道绑定。

[p112]
策略层。 可编程的支出控制正在两个生态里同时出现。Coinbase Agentic Wallets 在 Base 上提供带可编程限额的代付交易，Turnkey、Privy、Safe 等策略层则把白名单、支出上限和商户路由直接编码进钱包基础设施。卡这一侧，带发卡行自定义支出规则的令牌化凭证，通过大家熟悉的基础设施发挥同样的作用。

[p113]
5.3 尚未解决的问题

[p114]
目前没有一个通用的代理身份标准，能够把新兴的加密原生通道和已经存在的传统通道连起来。在一个生态里建立的声誉无法转移到另一个生态。

[p115]
争议缺少既有的处理机制。拒付窗口和举证要求当初是为人类速度、买方意图明确的商业设计的。当一个代理每小时执行数千笔交易，「单笔有争议的订单」这个概念，无法映射到几百次亚美分的 API 调用上。

[p116]
此外，责任在法律上仍然模糊。没有任何司法辖区确立了明确先例，来规定责任如何在授出权限的人、托管代理的平台、模型提供方和商户之间分配。

[p117]
这些缺口既是今天代理型商业中最重大的风险，也是传统支付生态中的现有机构最清晰的价值增量机会。

[p119]
6.1 代理型商业技术栈

[p120]
代理型商业需要在多个基础设施层之间协调，从代理如何通信一直到钱如何移动。没有任何单一标准能覆盖完整技术栈，而且这个格局在快速演变。

[p121]
代理型商业标准格局，各层级正在涌现的协议｜来源：Artemis，数据截至 2026 年 5 月

[p122]
这些标准合在一起，构成了代理型商业正在成形的基础设施栈，从通信和身份一直到授权和支付执行。

[p124]
x402 和 MPP 定义的是代理如何为机器原生资源付款，与此并行，另一批协议正在为「代理代表人类消费者、通过现有卡基础设施完成交易」的场景涌现。

[p125]
Visa TAP。 Trusted Agent Protocol 让商户通过经密码学签名的 HTTP 消息，验证某个 AI 代理确实被授权代表某位用户行事。TAP 在现有 Web 和商户基础设施之上加了一个标准化的信任层，商户不必大改自己的支付栈就能处理代理发起的交易。TAP 与 Cloudflare 共同创建，Shopify、Microsoft 和 Stripe 提供了输入，2025 年 10 月上线，早期采用方包括 Nuvei、Adyen 和 Stripe。对传统支付生态来说，TAP 是从现有卡基础设施通往代理发起商业的最直接路径。

[p126]
ACP（Stripe + OpenAI）。 Agentic Commerce Protocol 让代理通过现有商户结账流程、用卡支付完成购买。代理平台和商户必须互相预先批准才能发生交易，形成一个只有经审核参与者才能交易的策展式市场。付款由 Stripe 处理，OpenAI 在标准处理成本之上向商户收取一笔费用。

[p127]
UCP（Google/Gemini + Shopify）。 Universal Checkout Protocol 让代理直接在 Google 的产品面内完成购买，比如 Search AI Mode 和 Gemini 应用。商户保有客户关系的完整所有权，并在所有交易中仍是记录商户。该协议由 Google 和 Shopify 联合开发，参与方超过 20 家，包括 Etsy、Wayfair、Target 和 Walmart，支持 REST、MCP、AP2 和 A2A 集成。

[p128]
VIC（Visa）。 Visa Intelligent Commerce 是 2026 年 4 月发布的单一集成入口，让商户、收单方和代理平台参与代理型商业。这个平台与协议无关，通过一次集成就支持 TAP、x402、MPP、ACP 和 UCP。它提供令牌化、基于 passkey 的认证和可编程支出控制，允许用户设定金额上限、商户类别，或者要求实时批准。对商户来说，VIC 不需要逐个对接每一种代理协议。对支付生态来说，它把 Visa 定位成代理与现有商业基础设施之间的连接层，目前已有超过 100 家合作方，其中 30 家在 VIC 沙盒中积极构建。

[p129]
AP2（Google + 60 家合作方）。 Agent Payments Protocol 引入了经密码学签名的 mandate（授权书）作为代理授权的基础。Intent Mandate 记录代理可以代表用户购买的条件，Cart Mandate 记录某笔交易的具体商品和价格，Payment Mandate 授权最终付款。该协议与支付通道无关，支持卡、银行转账和加密货币。AP2 被设计成 A2A 和 MCP 二者的扩展，定位是一个可以架在多种支付协议之上的授权层。合作方包括 Mastercard、American Express、PayPal、Adyen、Coinbase 和 Salesforce。

[p130]
Agent Pay（Mastercard）。 Agent Pay 用 Mastercard 的令牌化技术创建代理专属的支付凭证。消费者在设定的参数范围内授权代理代表自己行事，代理使用消费者卡片的令牌化版本完成购买。支出限额、商户类别和其他护栏都是可编程的，并直接绑定到凭证上。

[p131]
6.3 趋同，以及规模化的条件

[p132]
加密原生协议和卡原生协议之间的界线已经开始模糊。MPP 现在通过共享支付令牌同时覆盖链上加密支付和法币支付，Visa 的 Card Specification SDK 被设计用来把协议延伸进基于卡的代理商业。实际效果是，一套机器支付框架可以越来越多地同时支撑稳定币流程和卡交易。

[p133]
对卡网络和发卡行来说，这开辟了一条进入代理支付流的路径，不需要商户去采用一套完全独立的技术栈。从另一个方向看，Stripe 在 2026 年 3 月增加了对 Base 上以 USDC 进行的 x402 支付的支持，把稳定币原生的支付流接进了更广的代理商业生态。

[p134]
方向指向的是趋同而不是竞争：银行卡更适合代理代表人类完成传统消费，稳定币更适合机器原生微支付，而混合工作流可能同时使用两种通道。

[p135]
要让这种趋同越过早期采用阶段，还有三件事需要发生：

[p136]
- 标准之间的互操作性需要成熟。 随着时间推移，代理应该能在单一工作流内组合使用 AP2 式的授权 mandate、x402 或 MPP 的支付执行、以及 TAP 或类似系统的信任与卡端验证，而不必为每一种组合做定制集成。
- 监管框架需要追上技术。 代理发起的交易、责任归属、跨境代理商业该如何处理，目前仍未定论，尤其是当这些系统开始跨多条支付通道和多个司法辖区运行时。
- 现有机构需要明确的角色。 处理全球大部分支付的这些机构，需要看清自己在技术栈中的位置：是做代理凭证的发行方，是做代理交易的处理方，还是做加密原生协议目前仍然欠缺的信任与争议基础设施的提供方。
七、应用场景

[p138]
今天交易量最大的场景是线索补全、数据抓取、推理与推理路由、以及网页搜索。线索补全是其中一个显而易见的高价值工作流，代理按次查询付费，拉取个人或公司档案、验证邮箱、补全 CRM 数据。

[p139]
除此之外，一条不断增长的服务长尾正在出现：社交媒体情报（抓取 LinkedIn、X 和 Reddit 数据）、图像与视频生成端点、Google Maps 查询、电话呼叫 API、代理式搜索。

[p140]
有一个例子能说明这件事的走向：人脸搜索端点，代理上传一张图片，收到全网范围内概率最高的身份匹配结果。这类小众但高价值的服务，永远不值得为它承担一个完整 SaaS 产品的开销，但作为一个按请求收费、代理可以发现并调用的 API 却完全说得通。随着生态成熟，这类有创造性的长尾场景很可能会大量涌现。

[p141]
代理在为什么付费，机器发起支出的早期品类｜来源：Artemis，数据截至 2026 年 5 月

[p143]
一个构建公司档案的研究代理，可以向多家数据提供方各花几美分查询，比较结果，选出最好的那份。总成本可能不到一美元。

[p144]
在传统模式下，同样的工作流往往需要向单一供应方订阅，且在需要的那一刻没有比价的能力。这是低摩擦支付所释放出的最清晰的商业形态之一。代理没有账号、没有事先谈好的合同、和卖方也没有长期关系。它发现端点、付款、评估输出，然后走人。

[p145]
这个模式的适用范围远不止数据补全。开发者可以把文档解析器、翻译服务、代码审查工具，或者其他 MCP 可访问的功能，暴露成一个付费端点。代理可以按需发现并调用这个工具，提供方不需要围绕它建一整个 SaaS 生意。这降低了成为机器经济中商户的门槛，也催生出一条专业化、按次付费服务的长尾。

[p146]
这个模式已经开始被产品化。Merit Systems 构建的 AgentCash 把钱包管理、商户发现以及对 420 多个付费 API 的访问，打包成面向 Claude Code 这类代理框架的单一集成。这个平台让代理无需逐个配置就能访问数百项付费服务，把 x402 和 MPP 上协议层支付的复杂度都抽象掉了。

[p147]
7.3 流式与计量服务

[p148]
不是所有代理支付都是单次请求与响应的交易。有些工作流需要在一段时间内持续访问某个资源。一个编码代理可能要连续消耗几个小时算力，一个监控代理可能持续接收行情数据，只为它实际用到的那部分数据流付费。

[p149]
MPP 的 session 就是为这个模式设计的。代理存入资金，边消费边增量付费，任务结束或质量低于预期时可以随时停止。商户按已交付的用量获得报酬，买方则不必为需求波动的场景承诺一份固定订阅。对于用量连续、不可预测、且与任务完成度紧密绑定的代理工作流，这个模式更合适。

[p150]
7.4 代理对代理服务

[p151]
代理型商业中一个标志性的场景，是代理直接与其他代理交易。单次用户请求可以触发一连串机器对机器的购买，一个代理把子任务分派给专门的服务：搜索、数据补全、算力、执行，每一项都在需要的那一刻被程序化地付费。

[p152]
这是一块全新的商业面。购买与购买之间没有结账页、没有购物车、也没有人工审批环节。工作流持续运行，每个代理评估并为链条中的下一个服务付费。如前文第四章所述，这已经是 x402 按交易笔数计的最大活动品类。

[p153]
这是代理自己创造出来的商业最清晰的例子之一。付款被直接嵌入工作的执行过程，让专业化的服务得以实时协调并交易。

[p154]
八、经济模型与价值归属

[p156]
上面这些场景有一个共同特征：高频、低价值、买卖双方之间没有事先存在的关系。服务这类商业的经济模型，和传统支付非常不同，而两个支付标准生态（x402 和 MPP）目前捕获价值的位置也不一样。

[p157]
代理型商业中的价值归属，x402 与 MPP 两个生态对比｜来源：Artemis，数据截至 2026 年 5 月

[p158]
在 x402 中，交易额流经 facilitator 层，中介方可以针对验证、结算和相关信任功能收取处理费。在 MPP 中，价值在交易层归属较少，更多归属到周边生态：聚合需求的平台、简化集成的工具，以及帮助买卖双方有信心交易的信任层或发现层。

[p159]
这个差异塑造了两个生态各自的扩张方式。x402 变现的是资金流中的中介角色，MPP 则把变现重心推向分发、路由和信任。对现有机构来说，关键问题是可持续的经济性最终会落在哪里。

[p161]
代理型商业让新商户进入市场变得异常容易。开发者可以用相对小的集成开销，把一个现有 API 放到 402 兼容的付费墙后面，同样的基本逻辑也适用于更广的机器支付生态。这是刻意为之的设计。x402 和 MPP 的构建目标就是降低供给侧的接入摩擦，让新服务更容易实现变现。

[p162]
容易进入并不等于可持续的经济性。 当新端点可以被快速上线、竞争性供给容易被复制，价值就会从单个商户身上转移到更难复制的那些层级。在电商领域，类似的动态把可持续价值推向了平台和支付基础设施，而不是被它们赋能的商户长尾；在代理型商业里，最强的结构性优势坐落在分发、信任和基础设施上。

[p163]
谁控制代理如何发现并路由到服务，谁就控制需求。谁构建出帮助代理在竞争供应方之间做选择的身份与声誉系统，谁就能降低欺诈、提升转化。而谁提供结算、合规与争议基础设施，谁就被嵌入了交易流本身。

[p164]
这正是传统支付行业天然有优势的地方。支付网络、发卡行和收单方花了几十年建设的能力，恰恰是代理型商业规模化时仍然需要的：身份核验、支出策略执行、欺诈识别、跨境结算、商户风险评估。

[p165]
新协议提供的是可编程性、速度，以及传统卡通道在极小额交易上难以匹敌的成本结构。但它们目前还没有提供现有机构量级的信任基础设施、监管覆盖或商户分发能力。

[p167]
9.1 这些协议如何对应现有监管

[p168]
代理支付协议无法干净地对应到现有的支付监管上。

[p169]
在 x402 式的模型里，facilitator 可能会临时持有资金、验证交付条件、再把款项释放给卖方。取决于这个角色如何设计、以及某个司法辖区如何解读，它可能触及资金转移、支付处理、托管或相关牌照框架。MPP 式的直连模型减少了专职中介的角色，但提出了另一个问题：当没有任何一方明确处在买卖双方之间时，与这笔交易相关的监管义务由谁承担？

[p170]
跨境复杂度又叠加了一层不确定性。一个司法辖区内的代理可能付款给另一个辖区的服务器，而基础设施或服务提供方还牵涉到更多辖区。现有跨境支付框架的构建前提是交易对手可识别、司法归属较清晰、交易流较慢，而代理交易把这些前提压缩掉了。对支付服务商来说，这意味着合规架构可能会从后台职能变成一种竞争差异化来源。

[p172]
两个协议早期的结算路径，都让稳定币监管与代理型商业的未来直接相关。在美国，GENIUS 法案为支付类稳定币发行方建立了联邦层面的牌照与储备框架，给基于稳定币的支付流提供了比此前更清晰的监管基础。

[p173]
对 x402 而言，活动一直与 USDC 紧密关联，尤其是在 Base 上，这给了这个生态一个相对亲机构的起点。但 x402 本身并不必然局限于单一稳定币或单一链，具体实现可以随 facilitator 和网络而变。

[p174]
对 MPP 而言，目前的实现包含了 Tempo 上的 pathUSD 这类加密原生结算机制，但协议的范围比任何单一通道都更宽，同时也被设计成支持共享支付令牌这类与法币挂钩的支付方式。

[p175]
对传统支付受众而言，稳定币合规问题之所以重要，是因为它决定了这些资金流能否被整合进受监管的金融基础设施。如果稳定币结算有明确的监管地位，它对银行、收单方和处理商来说就是一条更可行的、可以在其上构建的通道。如果监管处理在各辖区之间仍然割裂，机构采用的速度就会慢下来。

[p176]
9.3 与代理相关的特殊考量

[p177]
现有的 KYC 和反洗钱框架是围绕人类客户设计的。在代理型商业里，这个前提失效了。

[p178]
核心的合规问题变成了：出于识别、监测和监督的目的，真正相关的「客户」到底是谁？是把权限授给代理的那个人，是运营代理的平台，是给钱包充值的实体，还是三者的某种组合？这一点上的监管处理仍未定论。

[p179]
税务和申报义务面临类似挑战。一个代理可能在单次会话中跨多个司法辖区执行数千笔小额交易，产生现有系统当初并未设计承载的申报负担。买卖双方对彼此的身份、所在地或法律状态可能都只有有限的可见度。

[p180]
对正在评估这个市场的支付服务商来说，让代理交易在规模上可追溯、可审计、可申报所需的基础设施，本身很可能会成为一个重要的价值创造层。

[p183]
代理型商业已经开始运转，但整体仍处于早期发展阶段。协议存在，交易模式可见，而周边基础设施仍然建设不足。这创造出几个明确的增长与投资机会：

[p184]
卡与稳定币的混合结算。 对发卡行和收单方来说，最直接的机会之一是混合结算：前端用卡，后端用稳定币。持卡人体验保持不变，结算则转到稳定币通道上，支持更快的收款、连续的结算窗口和更低的跨境成本。

[p185]
这让现有机构有办法分享稳定币基础设施在速度和成本上的优势，同时不需要商户或消费者改变行为。随着代理型商业扩大规模，对于那些希望通过自己已经运营的基础设施接触机器发起支付流的机构，混合结算很可能会成为一条有吸引力的路径。

[p186]
协议趋同与互操作性。 x402 和 MPP 目前作为彼此独立的生态运行，结算通道、信任模型和商户基础都不相同。随着时间推移，代理需要能在协议之间路由交易，而不必为每一个协议做定制集成。

[p187]
趋同的早期迹象已经出现：MPP 同时支撑加密和卡关联的支付流，Stripe 在 Base 上对 x402 的支持则把稳定币原生支付接入了更广的支付基础设施。帮助代理为每种交易类型选择正确协议的互操作层，可能会成为技术栈中一个重要的控制点。

[p188]
跨境代理商业。 跨境活动很可能会是代理型商业的默认特征，而不是小众边缘情况。代理可以跨辖区发起交易，绕开现有合规体系所依赖的传统身份与居住地锚点。而在机器速度下处理合规、货币转换和辖区路由的基础设施仍不成熟。对具备全球覆盖的支付网络来说，这是现有能力的自然延伸，也是近期最清晰的差异化价值机会之一。

[p189]
代理成为商户。 今天代理主要扮演买方，但随着时间推移，它们也会成为卖方。随着构建和部署软件的成本继续下降，更多开发者、公司和工作流将有能力把专业化服务直接暴露给代理。这会显著扩大生态的供给侧，带来更多代理可访问的端点、更多小众服务，以及流经支撑它们的支付通道的更多交易量。

[p191]
代理型商业正在成形。x402 和 Machine Payments Protocol 在处理真实交易，商户和代理平台开始在其之上构建，周边的标准格局也开始围绕一组共同需求收敛：信任、身份、授权、结算。

[p192]
这个市场中正在浮现的交易模式是高频、亚美元、自主，且往往跨境的。协议解决的是速度、可编程性和成本。但要规模化进入受监管的金融体系，还需要现有支付玩家花了几十年建设的那些东西：信任基础设施、合规框架、商户分发和争议处理。

[p193]
这个缺口定义了机会，而 Visa 已经在市场的两侧都完成了布局。 TAP 和 Visa Intelligent Commerce 把卡基础设施连到更高价值的代理人交易，面向 MPP 的 Card Specification SDK 和对 x402 基金会的参与，则把 Visa 的触角延伸进机器原生的微支付。

[p194]
这个覆盖广度反映的正是贯穿全篇的趋同判断：宏观和微观两种交易模型可能起步于彼此独立的生态，但随着时间推移，它们很可能会通过共享的信任、身份和结算层连接起来。

[p195]
这个市场仍处于早期阶段，许多关键基础设施尚未定型。那些现在就参与建设信任机制、支出控制和协议互操作性的机构，最有可能在代理型商业走向规模化之后，继续占据核心位置。
