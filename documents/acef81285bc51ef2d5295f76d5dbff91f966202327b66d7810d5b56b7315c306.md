# 从需求到用例，AI帮我写

[p003]
做测试开发的，大概都经历过这个阶段：

[p004]
产品丢过来一份需求文档，你对着屏幕发呆——"这功能我得写多少条用例？边界条件怎么列？异常场景有没有遗漏？"

[p005]
然后就开始漫长的复制粘贴、查文档、对逻辑。一个功能模块写下来，半天没了。

[p006]
我上个月用WorkBuddy搭了一个测试用例生成智能体，现在说一句需求，它就能自动吐出完整的测试用例文档。

[p007]
今天把整个过程分享出来，手把手教你怎么搭。

[p009]
## 先说清楚我们要做什么

[p010]
我们要用 WorkBuddy 的 Skill 机制，创建一个专门生成测试用例的智能体。

[p012]
输入| 功能需求描述（可以是PRD截图、也可以是纯文字）  
---|---  
过程| WorkBuddy 自动分析功能点、拆解测试维度、生成用例  
输出| 可直接粘贴到测试管理系统的用例文档

[p015]
* **WorkBuddy** ：主框架，对话驱动
  * **Python** ：Skill 执行脚本，用 python-docx 生成文档
  * **Playwright** （可选）：如果需要从网页抓取需求文档

## 步骤二：编写生成脚本

[p027]
import sys from docx import Document from datetime import datetime  def parse_requirement(requirement_text):  lines = requirement_text.split('
')  features = [l.strip() for l in lines  if l.strip() and not l.strip().startswith('#')]  return features  def generate_testcases(features):  cases = []  for i, feature in enumerate(features, 1):  cases.append({  'id': f'TC-{datetime.now().strftime("%Y%m%d")}-{i:03d}',  'title': f'{feature} - 正常流程',  'precondition': '待补充',  'steps': [f'1. 执行{feature}操作', '2. 验证结果符合预期'],  'expected': '功能正常，无异常',  'priority': 'P1'  })  cases.append({  'id': f'TC-{datetime.now().strftime("%Y%m%d")}-{i:03d}B',  'title': f'{feature} - 边界值测试',  'precondition': '待补充',  'steps': ['1. 输入边界值（最大/最小/空值）', '2. 验证处理结果'],  'expected': '边界值处理正确',  'priority': 'P2'  })  return cases  def export_to_docx(cases, output_path):  doc = Document()  doc.add_heading('测试用例文档', 0)  for case in cases:  doc.add_paragraph(f"用例ID：{case['id']}")  doc.add_paragraph(f"标题：{case['title']}")  doc.add_paragraph(f"优先级：{case['priority']}")  doc.add_paragraph(f"前置条件：{case['precondition']}")  doc.add_paragraph(f"测试步骤：{case['steps'][0]}
{case['steps'][1]}")  doc.add_paragraph(f"预期结果：{case['expected']}")  doc.add_paragraph('---')  doc.save(output_path)  if __name__ == '__main__':  req_text = sys.argv[1] if len(sys.argv) >1 else ''  features = parse_requirement(req_text)  cases = generate_testcases(features)  output = f'testcases_{datetime.now().strftime("%Y%m%d_%H%M%S")}.docx'  export_to_docx(cases, output)  print(f"已生成 {len(cases)} 条测试用例：{output}")

## 步骤三：让WorkBuddy调用这个Skill

[p031]
在 WorkBuddy 中加载你的 Skill：

[p032]
cp -r testcase-generator ~/.workbuddy/skills/  
---

[p033]
然后在 WorkBuddy 对话框里说：

[p034]
"帮我分析这个功能并生成测试用例：用户登录模块，支持手机号+验证码登录，支持海外手机号，忘记密码可以重设。"

[p035]
WorkBuddy 会自动识别你的 Skill，调用脚本，生成用例文档。

[p038]
### 坑1：需求描述太模糊

[p039]
智能体生成用例的质量，取决于你输入的需求描述质量。建议输入时尽量包含：输入项、输出项、业务规则。

[p040]
### 坑2：没有维护用例编号规则

[p041]
建议在脚本里加入日期前缀（如），方便后续在测试管理系统里追溯。

[p042]
### 坑3：异常用例不够

[p043]
正向用例 AI 写得不错，但异常场景容易遗漏。我的经验是：自己再过一遍，特别关注网络异常、超时、数据格式错误这几个维度。

[p046]
搭好之后，用一个中等复杂度的功能模块测试，用例生成从4小时压缩到40分钟。

[p047]
不是完全替代人工审核，但**80%的基础用例不需要再手动写了** 。

[p050]
测试用例生成智能体的本质，是把"把功能点转成用例"这个重复劳动外包给AI。
